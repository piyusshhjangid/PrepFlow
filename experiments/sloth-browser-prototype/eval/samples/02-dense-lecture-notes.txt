Operating systems lecture 4: processes and scheduling

A process is a program in execution, together with its address space, open files and processor state. The operating system keeps a process control block for every process, and this block stores the program counter, the registers and the scheduling information needed to resume the process later. A context switch saves the state of the running process into its control block and loads the state of the next process, and because no useful work happens during the switch, frequent switching reduces throughput.

Processes move between several states. A new process becomes ready, a ready process is dispatched to the running state, and a running process either finishes, blocks while waiting for input or output, or is preempted and returned to the ready queue. The scheduler decides which ready process runs next. First come first served is simple but short jobs can wait behind a long one, which is called the convoy effect. Shortest job first minimizes average waiting time but needs a prediction of burst length and can starve long jobs. Round robin gives each process a fixed time quantum and rotates through the ready queue, so that response time stays reasonable; if the quantum is too large it behaves like first come first served, and if it is too small the cost of context switches dominates.

Priority scheduling picks the highest priority ready process, and aging gradually raises the priority of waiting processes to prevent starvation. Multilevel feedback queues combine these ideas by moving processes between queues according to how much processor time they have used.
