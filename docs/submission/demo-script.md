# PrepFlow demo script (2–4 minutes)

**Before the demo:** use fictional notes and a demo workspace. Verify the configured provider and database; do not describe a fake provider as Gemma. Keep the notes and exam date ready.

1. **Problem (15 seconds):** “A student preparing for several topics can lose time deciding what to study first. I built PrepFlow to turn their actual notes and available study time into a realistic next step.” Replace this with the friend's own words only after asking permission.
2. **Material (20 seconds):** show setup, exam date, daily availability, study days and a short source document. Explain that scanned PDFs are not supported.
3. **Analysis (25 seconds):** start analysis and show only stages returned by the server. Name the configured Gemma provider accurately.
4. **Review (25 seconds):** show extracted topics, evidence quotes, priority inputs and estimated minutes. Edit one estimate or weak flag and save.
5. **Plan (30 seconds):** generate or rebalance. Point out daily capacity, prerequisite order, fit status and any deferred workload. Explain that deterministic code chooses dates and durations.
6. **Today (25 seconds):** open Today, start or complete a task, then show the persisted completion and due/overdue revision.
7. **Progress (20 seconds):** show remaining work and completed study/revision time. Refresh to demonstrate persistence.
8. **Close (15 seconds):** explain local Ollama vs hosted inference, privacy tradeoffs, remaining limitations and the specific feedback still being collected.

Never show a fake screenshot, invented friend quote, or claim that a provider or deployment was tested unless it was.
