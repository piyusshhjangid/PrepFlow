# Submission checklist

- [ ] Confirm the exact event/challenge name, current dates, entry rules and required DEV tags.
- [ ] Complete a real friend test; obtain permission for any personal story or quote.
- [ ] Verify the actual Gemma provider/model on the demo environment; identify local vs hosted inference accurately.
- [ ] Run local build, tests, lint, typecheck, format and database integration checks.
- [ ] Deploy frontend, API and PostgreSQL; verify migrations, CORS, AI key location and the complete workflow.
- [ ] Capture genuine screenshots and a short demo recording.
- [ ] Fill the DEV draft with the friend's actual problem and feedback, without private details.
- [ ] Explain what Gemma does and which decisions stay deterministic.
- [ ] State limitations, local/hosted privacy differences and unresolved issues.
- [ ] Confirm repository URL, live demo URL, license and disclosure/tag requirements.
- [ ] Review the post and all attachments for secrets, workspace IDs and private study content.
- [ ] Publish through DEV only after the human has reviewed the final text and confirmed the target event.
